# Daily PM Research Update: 2026-11-14

## The Short Version

OpenAI shipped agent-initiated purchasing with ChatGPT Wallet, GitHub published a cross-agent skills spec that tries to solve portability before it becomes a lock-in problem, and Noah Shinn's Instinct data point (30% of users asking the agent to help with doctor visits, 5% on someone else's behalf) is a live read on how far people will actually let an agent act for them.

### OpenAI - ChatGPT Wallet Lets Agents Spend Your Money With Approval

**Source:** https://openai.com/index/introducing-chatgpt-wallet
**Credibility:** High (first-party product announcement)

**What happened:** OpenAI launched ChatGPT Wallet, a mechanism for agents inside ChatGPT Work, Codex, and dots to complete purchases using existing card protections, gated behind user approval at the point of transaction. This is OpenAI formalizing the "agent buys things for you" loop that's been implied by shopping and task-completion features for a while, but now with an explicit payment and approval layer built into the product surface.

**Key technical details:**
- Scoped to ChatGPT Work, Codex, and dots (OpenAI's agent products), not the general consumer ChatGPT app yet
- Purchases require user approval at time of transaction, not blanket pre-authorization
- Built on existing card protections (implies integration with standard card network dispute/fraud mechanisms rather than a new payment rail)
- Positioned as infrastructure for agentic commerce rather than a single feature

**Why it matters for PMs:** This is the fintech-meets-agent-autonomy question made concrete. Every open question about how much autonomy users will give an agent eventually collapses into "will they let it spend money." OpenAI's answer is: yes, but with a human-in-the-loop approval gate at the transaction point, not standing authorization. That's a meaningfully more conservative design than what Instinct is testing (see below), and it tells you where the frontier labs think the trust line currently sits. If you're building any agent feature that touches payments, OpenAI just set a default UX pattern: approve-per-transaction, not blanket delegation.

**Critical questions:**
- Does "user approval" mean a tap-to-confirm modal, or something more like a review-and-edit step? The friction level determines whether this is actually usable for anything beyond one-off purchases.
- What happens on disputed or erroneous agent purchases? "Existing card protections" suggests chargebacks work the same way, but who's liable when the agent misread an instruction?
- Will this expand to the consumer ChatGPT app, and if so, what changes about the approval model at that scale?

**Action you could take today:** If your product has any "AI agent does a task that costs money" feature on the roadmap, pull up this approval pattern and sketch whether your current design requires per-transaction confirmation or assumes standing authorization. That gap is where your next trust incident lives.

### GitHub - Agent Skills Spec Tries to Make Agent Capabilities Portable

**Source:** https://github.blog/ai-and-ml/github-copilot/build-once-run-on-any-agent-a-practical-guide-to-agent-skills/
**Credibility:** High (first-party engineering guide from GitHub/Copilot team)

**What happened:** GitHub published a practical guide to "agent skills," a pattern for building reusable capabilities that work across different agent harnesses (Copilot and others) rather than being locked to one vendor's agent implementation. The framing, "build once, run on any agent," is explicitly aimed at the fragmentation problem where every coding agent wants its own plugin or tool format.

**Key technical details:**
- Skills are packaged as portable capability definitions, not tied to a single agent runtime
- Positioned as a practical, adoptable pattern (a guide, not just a spec announcement) - suggests GitHub expects developers to start building against it now
- Comes right as Harrison Chase has been publicly needling the industry's term soup ("context engineering," "harness engineering") in favor of "goal engineering"

**Why it matters for PMs:** Every agent framework right now is reinventing tool definitions, and every team building on top of one is quietly accumulating vendor lock-in they didn't choose. If GitHub's skills pattern gets adoption, it changes the build vs. buy calculus on agent tooling: you can build a capability once and not re-architect it when you switch from Copilot to Cursor to a custom LangGraph agent. That's a big deal if you're staffing an agent platform team and deciding how much to invest in agent-specific integrations versus portable ones.

**Critical questions:**
- Is this actually a cross-vendor standard, or a GitHub pattern that only works cleanly with GitHub/Copilot infrastructure dressed up as "portable"?
- Who else is committing to this pattern? A portability standard with one implementer isn't a standard yet.
- How does this interact with MCP, which is already trying to solve a version of this problem?

**Action you could take today:** If your team has built agent tools or skills specific to one vendor's harness, read this guide and estimate the rework cost of making them portable now versus later when you're more locked in.

### Noah Shinn / Instinct - 30% of Users Are Asking Their Agent About Doctor Visits

**Source:** https://x.com/noahrshinn/status/2120634672883646807
**Credibility:** Medium (founder-reported usage stat, no independent verification, but specific and falsifiable)

**What happened:** Noah Shinn announced Instinct is integrating with Zocdoc for healthcare scheduling, and shared a usage stat alongside it: over 30% of Instinct users have already asked the agent for help with a doctor visit, and 5% of those requests were on behalf of someone else (a child, parent, or partner).

**Key capabilities:**
- Direct Zocdoc integration for healthcare appointment scheduling through the agent
- Usage data suggests healthcare task-completion is already a top use case for Instinct, not a hypothetical one being added speculatively
- The "acting on behalf of someone else" number (5%) is a specific, measurable signal about delegated/proxy agent use that's rarely reported

**Why it matters for PMs:** This is one of the most concrete data points we've seen all month on the open question of agent autonomy and trust. People aren't just asking an agent to summarize their calendar, they're asking it to navigate healthcare logistics for themselves and for dependents. That's a high-stakes, high-trust use case choosing itself organically, ahead of the product being purpose-built for it. For PMs working on anything agent-adjacent, this is a signal that the categories where agents get adopted fastest aren't the "obviously automatable" ones (scheduling a generic meeting), they're the ones with high personal friction (navigating a healthcare portal, picking a provider, booking for a kid) where the agent removes real cognitive load.

**Critical questions:**
- How is "asked Instinct for help" being measured? Does browsing count the same as completing a booking? The self-reported stat needs a denominator and a definition of completion.
- What does the proxy-use number (5%) imply about permissions and data handling when an agent acts for a third party who never consented to the interaction?
- Does Zocdoc integration change the take-rate economics, and does Instinct earn anything on the booking, which matters for the broader "will personal agents monetize via take-rate or subscription" question?

**Action you could take today:** If you're building anything with delegated or proxy use cases (one user acting for another), audit whether your permission and audit-trail model actually accounts for that pattern, most products are built assuming a 1:1 user-to-account relationship.

## The Thread

**Agent autonomy is being tested at the transaction layer this week, not the chat layer.** OpenAI's Wallet, Instinct's healthcare booking numbers, and even GitHub's push for portable agent skills are all converging on the same question: what happens the moment an agent needs to act in the world rather than just answer a question. The answer every player is giving right now is some version of "approval gate, not blanket trust," which tells you the industry consensus is still firmly on the cautious side of the autonomy spectrum, even as usage data (Instinct's 30%) shows users are already pushing agents into higher-stakes territory than the guardrails were built for.
