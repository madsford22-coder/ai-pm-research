# Daily PM Research Update: 2026-10-11

## The Short Version

LangChain published real numbers on a model router that cut coding-task costs by 64% with no quality drop, Notion keeps shipping agent infrastructure (skills libraries, custom agent workflows, CRDT internals) faster than almost anyone else in the category, and Pieter Levels is out with a three-post thesis that most future software won't look like software at all.

### LangChain - How Open SWE's Model Router Cuts Coding Costs 64% With No Quality Loss
**Source:** https://www.langchain.com/blog/how-to-build-a-model-router-in-the-harness
**Credibility:** High (first-party engineering writeup with a specific, falsifiable metric)

**What happened:** LangChain built a model router into Open SWE's coding agent harness that picks which model handles each step of a task, and reports it cut median cost per coding task by 64% with no measurable quality drop. This is the kind of claim that's usually marketing fluff, except it comes with a specific number and a described mechanism (routing inside the harness, not just picking a cheaper default model).

**Key technical details:**
- Router operates inside the agent harness, making per-step model decisions rather than a single model choice for the whole task
- Reported result: 64% reduction in median cost per coding task
- No measurable drop in quality on their internal benchmark (methodology not fully detailed in the post)
- Positioned as a reusable pattern, not a one-off optimization specific to Open SWE

**Why it matters for PMs:** Every PM shipping an agentic coding or automation feature right now is staring at a token bill that scales with usage, and "just use a cheaper model" is usually a quality tradeoff nobody wants to own. A router that matches model cost to task complexity is a real lever, not a hack, and it's the same instinct behind Vercel's AI Gateway expansion (see Quick Hits) and Cursor's multi-model approach. If you're building on top of LLMs and your cost structure is linear with usage, this is the first place to look before raising prices or capping usage.

**Critical questions:**
- What's "no measurable quality drop" measured against? Internal benchmark, user satisfaction, or task completion rate?
- Does routing complexity scale linearly with the number of models/providers you support, or does it get expensive to maintain?
- How much of this 64% is routing vs. just using newer, cheaper models that didn't exist when the original harness was built?
- Is this specific to coding tasks (where correctness is checkable) or does it generalize to subjective tasks where "quality" is harder to define?

**Action you could take today:** Pull your last 30 days of LLM API costs broken down by task type, and flag which tasks are using your most expensive model by default rather than by necessity. That's your router candidate list.

### Notion - Shipping Agent Infrastructure Faster Than Anyone: Skills Libraries, Custom Workflows, and CRDTs
**Source:** https://www.notion.com/blog/a-skills-library-for-every-agent
**Credibility:** High (first-party product and engineering blog posts)

**What happened:** Notion published three substantive posts in quick succession: a skills library for managing agent capabilities with the same editing/collaboration/governance model as Notion docs (led by Geoffrey Litt), a writeup on how their Customer Education team built a Custom Agent workflow using connected databases and MCP to keep Academy content current, and a deep technical post on how Notion handles concurrent editing with CRDTs. Taken together, this is a company treating "agent infrastructure" as core product surface, not a bolt-on feature.

**Key technical details:**
- Skills library: agent skills are managed with Notion's existing editing experience, collaboration, and governance, then reused across agents
- Custom Agent workflow: connects databases + MCP to spot content gaps, draft fixes, and auto-move approved updates into production docs
- CRDT post: describes a CRDT-based rich-text system that merges concurrent edits across Notion blocks without data loss, authored by four engineers on the team
- This follows their "Data Scout" post (personal data scientist connecting Snowflake to Notion) from the same window, suggesting a coordinated agent-platform push

**Why it matters for PMs:** The skills library is the most interesting piece here because it's the same "shared infrastructure beats individual tool" pattern we called out with Wispr Flow's team features: Notion is making agent skills something a team builds once and reuses, governed like any other shared doc. If you're evaluating whether to build agent capabilities as one-off automations or as a managed, shared layer, Notion just published their answer and the org pattern behind it.

**Critical questions:**
- Is the skills library actually used internally at meaningful scale, or is this three dogfooding case studies in a row to build a narrative ahead of a bigger agent platform launch?
- How does skill versioning and governance work when multiple teams depend on the same skill and one team wants to change its behavior?
- What's the failure mode when a Custom Agent workflow auto-moves an incorrect update into production docs? What's the review gate?

**Action you could take today:** If your team has more than two or three "agent" or automation scripts running independently, audit whether they could share a common skills/capability layer instead of being maintained separately. Notion's framing (govern like a doc, reuse everywhere) is a reasonable test for whether your automations need the same treatment.

### Pieter Levels - "Normies Won't Know They're Building Software" and the Case for Personal, Ephemeral Software
**Source:** https://levels.io/era-of-personal-software
**Credibility:** Medium (opinion/thesis from a prolific solo builder, not a controlled study, but high practitioner signal)

**What happened:** Levels published a three-post thesis this week arguing that "software is dead" in the traditional sense: most future software consumption will happen as personal, ephemeral generations inside AI chat apps, built by people who don't think of themselves as building software at all. He frames this as a shift from persistent, shipped products to disposable, single-use generations created on demand.

**Key patterns:**
- Core claim: normal (non-technical) users will generate one-off tools/interfaces via AI chat without ever perceiving it as "building software"
- Software stops being a durable artifact and becomes ephemeral output, generated and discarded per use case
- This is a direct challenge to the SaaS/app-store model: if nobody opens "an app" and instead gets what they need inside a chat interface, distribution and discovery look completely different
- Consistent with his historical pattern of building and shipping small, fast, solo products rather than platform plays

**Why it matters for PMs:** This matters less as a prediction and more as a stress test for your product's distribution assumption. If you're building a tool whose core value is "generate X," ask yourself honestly whether a user could get the same value by typing a prompt into ChatGPT or Claude tomorrow. Levels has a track record of correctly identifying where commoditization is headed before it's obvious (see his "AI commoditizes media until it's not special" post from last month), and this is the logical extension of that argument applied to software itself, not just content.

**Critical questions:**
- What's defensible if the generation itself becomes free and instant? Data, workflow integration, trust, and distribution all become more important than the generation step itself.
- Does this apply evenly across categories, or is it specific to simple utility software (calculators, converters, trackers) vs. complex systems with state, permissions, and integrations?
- Is "ephemeral software inside chat apps" actually a good user experience, or is it a novelty that collapses once users need to return to something they built last week?

**Action you could take today:** Take your product's core generation or output feature and try to replicate it in a raw ChatGPT or Claude conversation. If you can get 80% of the value in a prompt, that's your signal for where you need to invest in retention, data, or workflow lock-in rather than the generation itself.

## The Thread

**Agent infrastructure is becoming a product category of its own, and the winners are building the boring plumbing first.** Notion's skills library, LangChain's model router, Cursor's remote control for local agents, and Vercel's AI Gateway expansions this week are all the same bet: the differentiator in agentic products isn't the flashy demo, it's the unglamorous layer underneath (cost routing, skill governance, cross-device control, provider abstraction) that makes agents reliable and affordable enough to actually ship. Pieter Levels' "software is dead" thesis is the provocative bookend to this: if generation becomes free and instant, the infrastructure layer is the only thing left to compete on.
