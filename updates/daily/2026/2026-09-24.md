# Daily PM Research Update: 2026-09-24

## The Short Version

LangSmith dropped four major features in one day — red teaming, fine-tuning, trajectory tracing, and custom apps — signaling that agent observability is growing up fast. Meanwhile, Cursor shipped two deployment bots that bring AI into the "after the commit" phase, which is territory most AI coding tools still ignore.

---

### LangChain / LangSmith — Four-Feature Drop: Red Teaming, Fine-Tuning, Trajectories, Custom Apps

**Source:** https://www.langchain.com/blog/langsmith-engine-v2-redteam, https://www.langchain.com/blog/langsmith-fine-tuning, https://www.langchain.com/blog/langsmith-trajectories-tracing, https://www.langchain.com/blog/langsmith-custom-apps
**Credibility:** High (first-party announcements, all published same day)

**What happened:** LangSmith shipped four distinct capabilities on September 24. LangSmith Engine v2 adds Red Teaming to proactively surface agent issues before they hit production. LangSmith Fine-Tuning introduces SmithTune, a CLI that lets teams train specialized models without building data pipelines manually. Trajectories gives a conversational, human-readable view of every agent session to speed up debugging. And Custom Apps lets teams build interfaces directly on top of their LangSmith data, with auth, permissions, and hosting already handled.

**Key capabilities:**
- Red Teaming: automated adversarial testing to detect agent failure modes before production
- SmithTune CLI: post-training tooling that skips the data pipeline setup work
- Trajectories: a readable session replay view for long-running agents, making trace data navigable rather than raw
- Custom Apps: build and publish custom interfaces using your agent data, without managing hosting or auth separately

**Why it matters for PMs:**
This is LangSmith completing its arc from "observability tool" to "full production platform for agents." The four features address four distinct pain points: catching failures before they ship (red teaming), improving model quality over time without a dedicated ML team (fine-tuning), understanding what went wrong in a specific session (trajectories), and giving non-engineering stakeholders a window into agent behavior (custom apps). If you're building agents, this is now a serious competitor to building your own eval and debugging infrastructure from scratch — the build vs. buy calculus just shifted.

**Critical questions:**
- How does LangSmith's red teaming compare to building adversarial test suites internally? What attack categories does it cover and which does it miss?
- SmithTune claims to skip data pipeline setup — what are the actual quality constraints? Does this produce production-grade models or prototypes?
- Trajectories is described as "conversational" — does that mean it flattens complex parallel agent trees into a linear view, and does that introduce blind spots for multi-agent systems?
- Custom Apps handling hosting and auth sounds convenient — what are the data residency and security implications for teams with strict compliance requirements?

**Action you could take today:** If your team is running agents in production and debugging with raw trace logs, sign up for Trajectories access and spend 30 minutes replaying a real session from last week to see whether the new view surfaces anything your current process misses.

### Cursor — Rollouts and Security Review: AI Bots for Deployment Health and PR Vulnerabilities

**Source:** https://cursor.com/changelog/rollouts-and-security-reviewer
**Credibility:** High (first-party changelog, shipped September 23)

**What happened:** Cursor launched two new bots aimed at the deployment phase rather than the coding phase. Rollouts watches every change as it deploys and reports health per environment. Security Review analyzes every pull request for exploitable bugs and reports findings automatically. Both are available now.

**Key capabilities:**
- Rollouts: continuous monitoring of deploys across environments, surfacing health signals without requiring manual checks
- Security Review: per-PR exploit scanning that runs automatically, not as a gated step
- Both bots operate as part of the Cursor workflow rather than as standalone integrations

**Why it matters for PMs:**
Most AI coding tools stop at "code written and committed." Cursor is explicitly moving into the deployment lifecycle — which is where a lot of the real risk lives and where most teams still rely on manual processes or separate tooling. Security Review is particularly interesting: making vulnerability scanning a default, automatic part of every PR changes the security posture of teams using Cursor without requiring them to build or configure anything. For PMs thinking about developer platform strategy, this is Cursor expanding its surface area from "write code faster" to "ship code more safely."

**Critical questions:**
- What's the false positive rate on Security Review? If it flags too many non-issues, developers will start ignoring it — which is worse than not having it.
- Does Rollouts integrate with existing alerting systems (PagerDuty, Datadog, etc.) or does it create a parallel notification channel?
- Is Security Review running static analysis, dynamic analysis, or something model-driven? The methodology matters a lot for understanding what it can and can't catch.
- How does Cursor handle situations where Rollouts flags a deploy as unhealthy — does it suggest rollback, or just surface the signal?

**Action you could take today:** If your engineering team uses Cursor, check whether Security Review is enabled on your next PR and compare its findings against your existing security scanning tool. If they're catching different things, that's a meaningful signal about coverage gaps.

### Pieter Levels — AI Stripe Volume: US Is Exploding, EU Is Flat

**Source:** https://levels.io/ai-stripe-volume-us-vs-eu
**Credibility:** Medium (primary source Stripe data shared by a bootstrap founder, not an official Stripe publication — but Levels has a track record of sharing real data)

**What happened:** Pieter Levels published analysis showing that monthly payment volume from AI businesses on Stripe is "exploding" in the US while the EU remains flat. This comes the day after he shared that his own AI businesses crossed $10M/year in revenue with a 94.5% profit margin.

**Key signals:**
- US AI Stripe volume growing sharply; EU volume not following the same curve
- Framed as a market dynamics observation, not just personal data
- Posted same week EU regulatory divergence is a recurring theme (Mistral's €3B raise explicitly tied to "sovereign AI" positioning)

**Why it matters for PMs:**
The US/EU split in AI business payment volume is a real market structure signal for anyone thinking about where to launch, price, and prioritize. If EU AI businesses are generating materially less revenue, that affects both the competitive landscape and the viability of EU-first GTM strategies. It also raises a pointed question: is this regulatory drag (GDPR, EU AI Act compliance friction), market maturity, or something in the nature of what AI businesses the EU is producing? The answer changes what you'd do about it.

**Critical questions:**
- Is the EU flatness about regulatory barriers, user adoption lag, or the types of AI businesses being built there (more enterprise, slower sales cycles)?
- Does this hold when controlling for business size — are EU AI businesses just getting paid differently (invoices, not cards) rather than generating less volume?
- How does this interact with Mistral's positioning? If the EU market is flat on AI revenue, is "sovereign AI" a political/compliance product more than a commercial one?

**Action you could take today:** If you're making a market prioritization decision, pull your own revenue or activation data by geography and see whether your US/EU split matches this pattern. If it does, you may need to treat EU as a separate, slower GTM lane rather than a parallel launch.

## The Thread

**Agent tooling is maturing from "build and deploy" to "deploy and monitor."** LangSmith's four-feature drop and Cursor's Rollouts and Security Review bots both signal the same shift: the hard product work is no longer just getting agents (or AI-assisted code) out the door — it's knowing what happens after. Red teaming before launch, trajectory replay for debugging, deployment health monitoring, automatic PR security review — these are the features that indicate the category is growing up.

## Sit With This

Cursor shipped Security Review as an automatic, default-on bot that scans every PR for exploitable vulnerabilities. No configuration required — it just runs.

**For your product:** When AI catches a real security bug that your existing process missed, who owns the fix — and does the team trust the finding enough to act on it without manual confirmation? Think through what your "trust but verify" threshold is before the first false positive erodes the signal.
