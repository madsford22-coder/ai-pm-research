# Daily PM Research Update: 2026-09-17

## The Short Version

Teresa Torres built a working product feature without engineers, Notion shipped a skills library that turns agent governance into a team-level concern, and Anthropic quietly collapsed Claude's two modes into one — all pointing at the same thing: AI is shrinking the distance between "I have an idea" and "it's in production."

---

### Teresa Torres — Creating Aha! Builder: Concept to Code, No Engineers Required
**Source:** https://www.producttalk.org/creating-aha-builder-concept-to-code-no-engineers-required/
**Credibility:** High (first-person account from a recognized PM practitioner, published on her own platform)

**What happened:** Teresa Torres published a walkthrough of how she built "Aha! Builder," a feature for her continuous discovery practice tool, entirely without engineering help. The piece (with accompanying video) documents her going from concept to working code using AI-assisted development tools. This is the same Teresa Torres who wrote the book on continuous discovery — watching her personally navigate the no-engineer-required workflow is a signal worth paying attention to.

**Key patterns:**
- Concept-to-code is no longer theoretical for non-engineers. Torres is a PM and author, not a developer, and she shipped something real.
- The workflow she's documenting aligns with her broader continuous discovery philosophy: tight feedback loops, fast iteration, direct contact with the problem.
- This is also a product decision in itself: building internal tooling to support her own methodology, then sharing the process publicly as a teaching artifact.

**Why it matters for PMs:** The question "should we build this or wait for engineering capacity" is changing. Torres is modeling a pattern where PMs prototype and sometimes ship production features themselves — which changes the PM's role in discovery, prioritization, and delivery. If you're a PM who hasn't tried vibe coding a real feature yet, this is the clearest invitation from a credible voice in the field. It also raises the stakes on what "no engineers required" actually means for scope, quality, and maintenance.

**Critical questions:**
- What's the maintenance story? Features built without engineers can create hidden technical debt or become orphaned quickly.
- How does this change the PM/engineer relationship when PMs can ship? Does it reduce friction or introduce new coordination problems?
- Is this replicable across product contexts, or does it only work for internal tools and low-stakes features?
- What happens when these vibe-coded features need to scale or integrate with more complex systems?

**Action you could take today:** Pick the smallest internal workflow problem on your team — a spreadsheet you maintain manually, a report you generate by hand — and spend 90 minutes trying to vibe code a solution. Don't aim for production. Aim for something that works once, just to calibrate your own floor.

### Notion — A Skills Library for Every Agent
**Source:** https://www.notion.com/blog/a-skills-library-for-every-agent
**Credibility:** High (first-party product announcement from Notion, authored by Geoffrey Litt)

**What happened:** Notion shipped a centralized skills library that lets teams create, manage, and govern agent skills using Notion's existing editing and collaboration infrastructure. The key move: skills are now a first-class object in Notion, managed with the same familiar UX as pages and databases, then deployed to agents across the workspace. This pairs with the already-shipped Vercel changelog update showing the Skills CLI now supports Notion-hosted skills — so this is already in the ecosystem, not just a Notion-internal feature.

**Key capabilities:**
- Teams can author agent skills using Notion's editor, with the same permissions and collaboration model they already use for documents.
- Skills can be shared across agents — write once, deploy to many agents.
- Governance is built in: access controls, versioning, and collaboration apply to skills the same way they apply to pages.
- The Vercel Skills CLI integration means skills authored in Notion can be used outside Notion, in developer-built agents.

**Why it matters for PMs:** This is the team-infrastructure play for agents. Individual AI tools are easy to adopt and nearly impossible to scale consistently. What makes agent capabilities sticky at the team level is shared, governed infrastructure — and Notion just built that. The pattern here mirrors what Wispr Flow did with Team Dictionary: take something individuals were doing inconsistently and make it a shared, managed asset. For PMs building on top of AI tooling, this is the template for what "enterprise-ready agents" starts to look like: not just capability, but governance and reuse.

**Critical questions:**
- How does skill versioning work when agents are using a skill in production and someone edits it?
- What's the discoverability model? How do teams know which skills exist and which to use?
- Does this create a new role — something like a "skills curator" — or does it distribute that responsibility to whoever builds the agents?
- How does Notion enforce quality on skills? A poorly written skill deployed to many agents could cause consistent failures at scale.

**Action you could take today:** If your team uses Notion and has started building internal agents, map out the skills those agents use and check whether any are duplicated across agents. That duplication is the exact problem this feature solves — and identifying it now gives you a concrete reason to evaluate the skills library.

### Anthropic — Claude Cowork and Chat Are Now One Claude
**Source:** https://simonwillison.net/2026/Sep/16/one-claude/
**Credibility:** High (Simon Willison tracking a product change; Willison is a reliable technical observer of AI product changes)

**What happened:** Anthropic merged Claude's two distinct modes — Cowork (the collaborative, longer-context work mode) and Chat (the conversational mode) — into a single unified Claude experience. What had been two separate surfaces is now one. Simon Willison noted this on September 16.

**Key technical details:**
- Users no longer need to decide which mode to enter before starting an interaction.
- The unified interface presumably adapts to the nature of the conversation rather than requiring users to preselect a context.
- This follows a broader pattern of Anthropic simplifying the Claude product surface after earlier expansion.

**Why it matters for PMs:** Mode-selection is a classic UX tax. Every time you ask a user to choose a mode before they've done anything, you're front-loading cognitive load onto a moment when they don't yet know what they need. Collapsing modes into a single adaptive experience is almost always the right call once a product matures enough to infer context — and it's a useful product decision to study. The harder question is: what capability or clarity did Anthropic give up by removing the explicit mode distinction? Separate modes exist for a reason, usually to set expectations or route different UX flows. The merge suggests Anthropic is confident the model can handle context-setting without user intervention.

**Critical questions:**
- Were Cowork users getting meaningfully different outputs than Chat users for the same prompts? If yes, how does the unified experience handle that?
- Does collapsing modes reduce clarity about what Claude is optimized for in a given session?
- Is this a UX simplification or a capability merge? Worth watching whether power users feel something was lost.
- How does this affect enterprise deployments where different use cases might have been routed to different modes?

**Action you could take today:** If you have a product with multiple modes, entry points, or "which version do you want?" prompts — audit whether users are choosing correctly or just picking the default. If most users pick the default, that's a signal the modes aren't doing the work you think they are.

## The Thread

**The gap between idea and shipped feature keeps shrinking — and the implications for how PM teams work are only starting to surface.** Teresa Torres building her own feature without engineers, Notion making agent skills a managed team asset, Anthropic removing the "which mode?" decision entirely: each of these is a different version of the same compression. Less friction between intent and output. The open question — which none of these directly answer — is what happens to the coordination, quality, and ownership structures that friction was quietly holding in place.
