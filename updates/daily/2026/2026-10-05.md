# Daily PM Research Update: 2026-10-05

## The Short Version

OpenAI started shipping ads into ChatGPT and a new attribution stack to go with them, Notion keeps building the connective tissue for agent memory and skills, and Noah Shinn's Instinct just made the jump from single-user agent to something that acts for a whole group chat, each one forcing the same question: how much do we actually trust an AI system to act on our behalf, and who's paying for that trust.

### OpenAI - ChatGPT gets a native ads format, with attribution and measurement built in
**Source:** https://openai.com/index/new-chatgpt-ads-format-and-measurement
**Credibility:** High (first-party product announcement)

**What happened:** OpenAI introduced a new visual ad format inside ChatGPT, along with expanded measurement tools, attribution partnerships, and brand suitability controls for advertisers. This is the first time OpenAI has built out a full advertising stack (format + measurement + attribution) rather than just experimenting with sponsored placements.

**Key technical details:**
- New visual ad format designed specifically "for the way people use AI" (conversational, not banner-based)
- Attribution partnerships to let advertisers tie ChatGPT exposure to downstream conversion
- Brand suitability tooling, implying some kind of content/context classification to keep ads away from sensitive conversations
- Published same day as a separate post on EU text provenance/watermarking rules, suggesting OpenAI is bundling monetization moves with compliance moves

**Why it matters for PMs:** This is OpenAI finally answering the "how does this become a real business beyond subscriptions and API tokens" question, and doing it in the most trust-sensitive surface they have. If you're building anything that mixes assistant trust with commercial intent (recommendations, search, shopping), this is the reference case to watch: does ad load inside a conversational interface degrade perceived neutrality? Every PM who has debated "sponsored" labeling in a feed now has a much bigger, much higher-stakes version of that debate to study.

**Critical questions:**
- Does OpenAI disclose when a ChatGPT answer is influenced by an ad placement, and how is that disclosure rendered inside a conversational UI where there's no obvious "feed" to label?
- What happens to user trust metrics (session length, query complexity, willingness to ask personal/financial questions) after ads roll out broadly?
- How does "brand suitability" get enforced in a system where the model generates the surrounding context dynamically, not a fixed page?

**Action you could take today:** If your product has any assistant or chat surface with monetization ambitions, write down your own bright line today, before you have to improvise one under pressure, for what kind of commercial content can appear in a conversational response and how it gets disclosed.

### Notion - A skills library and shared memory system for agents, now with a CRDT backbone explained
**Source:** https://www.notion.com/blog/how-notion-handles-concurrent-editing-with-crdts
**Credibility:** High (first-party engineering blog, technical detail included)

**What happened:** Notion published an engineering deep-dive on how it handles concurrent editing with CRDTs (conflict-free replicated data types), explaining the system that merges concurrent edits across blocks without losing anyone's work. This lands in the same window as Notion's other recent posts on agent skills libraries and shared agent memory ("Lore"), making clear the CRDT work isn't just a nice technical story, it's the substrate that lets multiple humans and multiple agents edit the same workspace at once without stepping on each other.

**Key technical details:**
- CRDT-based rich-text system merges concurrent edits at the block level
- Built by a team spanning Angelique Nehmzow, Emma Guo, Fabricio Pontes Harsich, and Stephan Boyer
- Positioned explicitly as infrastructure for "anyone's work," meaning both human collaborators and, implicitly, agents writing into the same pages

**Why it matters for PMs:** As agents start writing into shared documents alongside humans (Notion's Custom Agents, Lore memory, skills library all point this direction), the unglamorous conflict-resolution layer becomes the actual product risk. A chat UI for an agent is easy. An agent that silently overwrites a teammate's edit because your merge logic doesn't handle concurrent non-human writers is how you lose trust in one afternoon. This is the kind of infrastructure choice that looks invisible until it breaks, and then it's the whole story.

**Critical questions:**
- Does Notion's CRDT model treat agent edits differently from human edits (e.g., different conflict priority, audit trail, revert path)?
- What's the user-facing recovery experience when an agent's edit and a human's edit collide, does the user even see that it happened?
- How does this scale when dozens of agents (per Notion's "skills library for every agent" push) are all writing concurrently?

**Action you could take today:** If your product lets any agent write into shared, multi-user state, audit today whether your conflict resolution treats agent writes as first-class citizens or as an afterthought bolted onto human collaboration logic.

### Noah Shinn / Instinct - Instinct now works in group chats, not just for one person
**Source:** https://x.com/noahrshinn/status/ (per tracked people activity, 2026-10-05)
**Credibility:** Medium (founder tweet, no full product documentation reviewed)

**What happened:** Noah Shinn announced that Instinct, the invite-only personal AI agent, can now be added to group chats, where it works on behalf of the entire group rather than a single user. This is a meaningful expansion from Instinct's original one-agent-per-person model.

**Key capabilities:**
- Early access users can add Instinct directly into a group chat
- The agent acts "for the entire group" rather than maintaining a single user's context and preferences
- Builds on Instinct's existing channel model (text, call, no dedicated app) by extending it to multi-party conversations

**Why it matters for PMs:** Instinct's whole pitch has been "one agent, one person, acting with your credentials." Group chats break that cleanly single-owner model: whose credentials does the agent use when booking something for five people? Whose calendar does it check? This is the open question in `context/open-questions.md` about agent autonomy and trust, now playing out in the messiest possible context, a group of people who didn't all individually opt into giving an agent access to their stuff.

**Critical questions:**
- When Instinct acts in a group chat, whose payment method, calendar, or credentials does it default to, and how is that negotiated or disclosed to the group?
- Does adding Instinct to a group chat require consent from all members, or just the person who added it?
- How does Instinct handle conflicting instructions from different people in the same thread?

**Action you could take today:** If you're building any multi-user agent feature, write out today who the agent is accountable to when two users in the same thread give it contradictory instructions, that ambiguity is where group-agent products either win trust or lose it fast.

## The Thread

**Shared state is becoming the real bottleneck for agent products, not model quality.** Notion's CRDT explainer, Instinct's group-chat expansion, and Thomas Wolf's "the database disagreed" post are all variations on the same problem: once more than one actor (human or agent) touches the same state, you need real infrastructure for conflict, consent, and verification, not just a smarter model. This week's OpenAI ads move adds a parallel thread: once an assistant has commercial incentives baked into its answers, "whose interest is the agent serving" becomes a trust question that infrastructure alone can't solve.
