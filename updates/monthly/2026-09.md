# September 2026 Research Summary

The build-versus-buy calculus fundamentally repriced this month. Julie Zhuo published a widely-read piece arguing that vibe coding has crossed a threshold where custom-built internal tools cost less in friction and money than adopting third-party software, and Pieter Levels published the receipts — $25K/month in SaaS replaced with tools he built himself, including a $249/month Scrapingbee plan swapped for a $1/month custom scraper. The question isn't whether this is happening anymore; it's which product categories are actually defensible against it.

The deeper pattern underneath is that the hard parts of scaling and winning in AI don't get easier just because AI democratizes access to building. Stripe published a playbook for scaling AI adoption across an entire organization (context, governance, shared skills infrastructure), and Perplexity shipped hybrid compute that keeps sensitive data local while cloud handles the rest — these are the infrastructure problems that actually matter once you get past the "let's build this" moment.

## What Matters

- **The vibe-coding threat is real for specific product categories, but not all.** Pieter Levels replaced $249/month Scrapingbee with a custom scraper; Julie Zhuo made the case that the friction of adopting, learning, and integrating third-party software is now higher than building replacements for internal workflows. The categories most at risk are single-function API services (data scraping, light transformation, narrow use-case SaaS) where the value prop is "we handle complexity." Network effects, regulatory moats, and genuine complexity remain defensible. If your product is horizontal productivity software (project tracking, reporting, communication tooling) where switching costs are low and workflows aren't deeply complex, you're in the crosshairs.

- **Context, governance, and shared skills are where enterprise AI adoption actually stalls.** Stripe's "company brain" framework identifies three layers most orgs get wrong: shared context (agents don't know your business), governance (teams make inconsistent policy choices), and shared skills infrastructure (everyone rebuilds the same agent capabilities independently). LangChain shipped context modes for multi-agent systems (fork or isolate a subagent's context, cutting token spend and latency), and AWS published a production-grade memory lifecycle pattern for agents. The signal is consistent: infrastructure layer problems are now the limiting factor, not model capability.

- **Privacy architecture is becoming a product differentiator, not just a compliance checkbox.** Perplexity shipped hybrid compute on Mac where sensitive file analysis runs locally and cloud handles the rest — the user doesn't manage the split, the agent orchestrates it. Cursor launched self-hosted machines for Cloud Agents so enterprise teams can keep codebase and IP entirely on-premise. OpenAI connected ChatGPT to EHR systems for healthcare organizations. The pattern: "we have SOC 2 compliance" is table stakes. "Your data never leaves your device" is competitive differentiation. For regulated industries and teams with sensitive workflows, this changes the adoption conversation entirely.
